GPT / Codex / Claude が続きを触るときの決まりごと。読者像そのものは `AGENTS.md`「0. 読者（ペルソナ）」。

## 1. 改名: サイソクAIニュース → サイソクニュース

- 名前・タグライン・説明文は `site.config.ts` だけ（name / shortName / siteName = サイソクニュース、nickname = サイソク、
  formerName = サイソクAIニュース、tagline = 仕事とお金の“旬”を、どこよりも速く。）。題名・OG・RSS・manifest・フィードはここを読む。
- JSON-LD（`lib/publisher.ts`）の `alternateName` に旧名を残す。**消さない**（Google が同じ媒体とつなげるため）。
  `scripts/check_search_identity.py` も「name が新名・alternateName に旧名」を確かめる。
- ドメイン・URL は変えていない。content/ の記事本文は書き換えていない（古い本文・古い SNS 文面に旧名が残るのは正常）。
- そのほか: メルマガの送信者名・件名（`scripts/newsletter.py`・`lib/newsletter/*`）、プッシュ通知の既定の題名（`public/sw.js`）、
  カバー画像・カード画像のサイト名（`app/cover`・`app/card`）、ロゴ（`lib/wordmark.tsx`）、まとめ投稿のリンクカード（`morning_digest.py`・`bluesky_post.py`）、
  /about・/editorial-policy の文。朝のまとめ投稿の「今朝のAIニュース3本」は AI の記事だけを選ぶので、その見出しはそのまま。

## 2. 読者像は `scripts/persona.py` の1か所

- `SYSTEM_BLOCK`: 記事の生成の system に入る（`main.SYSTEM_INSTRUCTION_BASE` の末尾。動画・公式フィード・話題・速報・角度記事すべて）。
- `WORK_MONEY_FIELD`: 記事の `work_money` 欄の書き方（各プロンプトの末尾）。
- `SNS_BLOCK`: Threads/X の紹介文の切り口（`threads_hooks.prompt_block`）。
- `ADVICE_RE`: 儲け話・投資助言・あおりの言い回し（work_money と SNS の機械チェック）。
- `PRIORITY_LANES`・`PRIORITY_TOPIC_RE`・`SPORTS_DAILY_CAP`・`sports_scope()`: 幅広い話題の配分とスポーツの範囲。
- `is_persona_topic()`・`topic_boost()`: 配信用の記事選び（はてなブログの下書き）。

## 2.5 伝え方（オーナー決定「とにかく伝わりやすい文章」）

- `persona.PLAIN_STYLE`: 詳しい先輩が忙しい会社員に話すように。です・ます調で少し会話っぽく（ざっくり言うと／つまり／たとえば）、
  1文は平均40字以内・1文1つ、専門用語は初出で言い換え、身近な例えを1つ、硬い言い回し（することが可能です／を見据える／において 等）なし。
  中身と分量は減らさず、事実確認も緩めない。記事の system（`SYSTEM_BLOCK` に含む）・work_money・かんたん版・SNS（`SNS_BLOCK`）・
  解説ページ（`evergreen.SYSTEM`）・はてなブログの下書きに入る。
- はてなブログの下書きは機械チェックもある（`crosspost_drafts.style_problems`: 平均の文の長さ40字・`persona.STIFF_RE`・冒頭「ざっくり言うと」）。
  当たれば作り直し（数字の照合は従来どおり）。記事の品質ゲートには硬さのチェックを入れていない（本数を落とさないため）。

## 3. 記事の「仕事・お金にどう活かせる？」欄

- スキーマの `work_money`（`{relevance: high|medium|low, points: [1〜3文]}`）→ 記事 JSON の `workMoney`。
  `main.py`（動画）・`web_articles.py`（公式フィード・幅広い話題・話題のニュース・速報レーン）・`angle_articles.py`（`build_web_record` 経由）。
  `evergreen.py`（使い方・料金の解説）は `work_money`（文の配列）→ `workMoney`。PROMPT_VERSION は上げていない（全ガイドの作り直しを起こさないため。
  次に作り直されたものから付く）。
- 品質ゲート（`scripts/quality.py`）は**緩めていない**。足したのは:
  - 形: 新しい web 記事に workMoney が無ければ不合格。1〜3個・長すぎ・`ADVICE_RE` に当たれば不合格。
  - 事実確認: `_article_for_check` が本文より前に欄を入れる（長い記事でも切られない）。FACT_PROMPT に、
    元に無い金額・節約額・収入の見込み、提供前のものを今使えるように書くこと、売買のすすめ・相場予想を必ず問題にする指示を追加。
  - 外科的な修正（大きなニュース）も欄を直せる。全部削られたら欄が無くなり形で落ちる。
- 動画記事（main.py）はもともと事実確認ゲートが無い経路なので、プロンプトの指示だけ（変更なし）。
- 表示: `components/WorkMoneyCard.tsx`。記事ページは判定カードの下、解説ページは結論の下。欄の無い古い記事には出ない。

## 4. SNS

- 書き出しの型は13型を残して2型を足した（`use_case` 活用型・`money` お金インパクト型）。直近の型を避ける・反応の弱い型を後回しにする仕組みはそのまま。
- `threads_post.openers`: workMoney が high で提供中・日本で使えるときだけ「これ、明日からの仕事で試せます。」、料金に金額があるときだけ「まず料金から。」。
- 返信（詳細）の要点に「仕事・お金：…」を1つ（workMoney の1つ目。low・長すぎ・ADVICE_RE は使わない）。
- `threads_voice`: お金・制度・不動産・ビジネスの記事に「money」の一言・問いかけ。売買はすすめない。
- はてなブログの下書き（`crosspost_drafts.py`）: 記事は `pick_top(persona_topics=True)`（AI・ビジネス/お金/投資・不動産・
  税や補助金などの制度。スポーツなし）。「自分にどう関係する？」の立場は「会社員として仕事で／副業・独立を考えている人／お金・資産づくりの面で」から
  本当に関係するものだけ。数字の照合はそのまま、ADVICE_RE に当たれば作り直し。ワークフロー（hatena.yml）は変えていない。

## 5. 幅広い話題の配分（本数は減らさない）

- レーンの順: ai → business → public（毎巡2本まで試す）→ 残りは時刻で回す → sports は最後。
- 同じ順位の候補の中では、お金・投資・不動産・起業/副業・税や補助金の語がある見出しを先に。
- スポーツ: 1日 `SPORTS_DAILY_CAP`（4本）まで。超えた候補は見送り扱いにせず次の日へ（mark しない）。
- スポーツの範囲（オーナー決定）: 日本のリーグ・チームと海外で活躍する日本人選手だけ。海外選手・リーグそのものは扱わない。
  世界的な大会（五輪・パラ・世界陸上・FIFA W杯・WBC・ラグビーW杯・世界水泳 など）は例外で海外選手も扱う。
  判定は `persona.sports_scope()`（幅広い話題の足切り `broad_prefilter`・毎朝の見逃しチェックの他社の見出し）＋スポーツのジャンルのプロンプト。
  話題のニュース（Googleトレンド）はもともとスポーツを除外しており、そのまま。
- テスト: `tests/test_persona.py`。
