# SNS 動画 v2（試作・未投稿）2026-11-02

SNS 投稿（Threads 中心。X / Facebook / Bluesky も）に付ける 15〜30秒の縦型動画を自動で作る仕組みの試作。
**投稿処理にはまだ組み込んでいない。スケジュールも無い。** 既存の `scripts/shorts.py` / `shorts.yml`（手動）はそのまま。

## ファイル

| 場所 | 役割 |
|---|---|
| `scripts/shorts_v2.py` | 台本（LLM・記事の事実だけ）→ 1文ずつ音声合成 → 字幕を文節で区切って時刻づけ → 3デザインで描画 → 品質ゲート |
| `scripts/video_gate.py` | 品質ゲート `check_video()`（形式・音・絵・文字・事実・クレジット）。不合格は理由つきで返し、例外を投げない |
| `scripts/sns_video.py` | 投稿処理への入口 `video_for_post()` と `post_with_fallback()`（失敗時の約束） |
| `tests/test_video_gate.py` | ゲートと約束の単体テスト（壊した動画で落ちることも確認） |
| `tests/test_shorts_v2_golden.py` | 決まった台本・合成音・合成写真で3デザインを 270x480/10fps で書き出す構造テスト（ネット・LLM 不要） |

## デザイン

- **A 報道テロップ型**: 写真を全面にそのまま（暗くしない・ぼかさない）、下だけ影、白い太字テロップ、赤「速報」、企業色の縦線、右上にロゴ。
- **B 大きな文字型**: 上半分に写真（そのまま）、下半分は紺の面に大きな字幕。要点ごとに写真の切り取りを切り替える。数字には赤い下線（黄色は使わない）。
- **C 公式ページ型**: 公式の発表ページをスマホ幅で撮影してゆっくりスクロール、出典を表示。撮影してよいのは公式発表の写真と同じサイト、または公式見張り（radar-official）の記事だけ。ニュースサイトが出典の記事は「数字カード型」になる。

共通: 最初の0秒から大きな「つかみ」、要点3つ（数字があれば数字カード）、「使える？」（記事の verdict の値を札で表示）、締め2秒以上（詳しくはサイソクで・URL・音声と画像のクレジット）。
文字は Threads/Reels/TikTok の UI に隠れない範囲（下20%・右12%・上150pxを避ける）にだけ置く。

## 品質ゲートが保証すること（不合格なら動画は付けない）

- 形式: H.264 High + AAC 48kHz、yuv420p、1080x1920、30fps、5〜45秒、faststart、24MiB 以下。
- 音: -14 LUFS ±1.5、ピーク -1.0 dBTP 以下、冒頭と締め以外に1秒を超える無音なし、字幕がナレーションの間ずっと出ている、つかみが0秒から出ている。
- 絵: 真っ黒・単色の画面が0.5秒以上続かない。
- 文字: 描いたときに測った枠が自分の箱と安全領域からはみ出さない、最小サイズ以上（入らないときは縮めずに不合格）、豆腐なし、コントラスト比 4.5（48px以上は3.0）以上。
- 中身: 画面と読み上げの数字・英字の名前・「」の語・長いカタカナが記事 JSON にある、評価語（最大・初など）は記事にあるときだけ、数字カードは記事の表記どおり、題が記事と同じ話、クレジット（VOICEVOX・画像・URL）が出ている。
- production は VOICEVOX の声が必須。edge-tts（試作の声）の動画は投稿に付かない。

## 失敗時の約束（組み込み時の契約。`scripts/sns_video.py` 冒頭）

1. `video_for_post()` は例外を投げず、失敗はすべて `None`。
2. `None` なら投稿は動画なしで今までどおり（文面・画像・リンク・時刻は変えない）。動画は 240秒で打ち切る。
3. 返すのはゲート合格・VOICEVOX の動画だけ。ファイルの大きさが report と違えば付けない。
4. 動画付き投稿がはっきり断られたときだけ動画なしで出し直す。受理不明（時間切れ等）は再送しない。
5. 既定では無効（`SNS_VIDEO=on` で有効）。

## 組み込み時の注意（調査結果）

- Buffer（GraphQL `createPost`）は動画を**公開 URL** で受け取る（`assets: [{video: {url}}]`）。署名付き・期限つき URL は不可。Buffer は投稿時に取りに来るので、それまで消さない。Cloudflare のボット対策で弾かれない経路にする。
- Facebook / Threads / Bluesky は `assets`（動画）と `linkAttachment`（リンクカード）を同時に指定できない。動画付きのときリンクは本文・返信・Facebook の最初のコメントに置く。
- 厳しい側の共通条件: 3〜90秒（Facebook リール）、100MB 以下（Buffer 経由の Bluesky）。v2 は 15〜30秒・3〜8MB 程度。
- X は文書上 1280x1024 までの記載が残る（実際は 1080x1920 も受け付け、720p に変換されることが多い）。断られたら 720x1280 で出す。
- Bluesky 直接投稿: `getServiceAuth` → `video.bsky.app` の `uploadVideo` → `getJobStatus` → `app.bsky.embed.video`（aspectRatio 1080x1920）。1日の上限は `getUploadLimits` で確認。
- 置き場所: R2（公開バケット＋独自サブドメイン、30〜60日で自動削除）。1日10本×8MB なら月 0円（無料枠内）。KV は1値25MiBで入るが、無料枠1GBを超え、反映の遅れもあるので R2 推奨。
- GitHub Actions: リポジトリは公開なので分は無料。VOICEVOX（docker）を使う。

## 未確認・残り

- 本番の声（VOICEVOX）での書き出しは CI で未実施（この Mac に docker が無い）。
- 「使える？」の文は LLM が記事の判定・かんたん版から書くが、意味の言い換えまではゲートで見られない（数字・名前・評価語だけ機械で照合）。
- C の公式ページ撮影は表示崩れ（クッキーバナー等）を固定表示の非表示だけで避けている。サイトによっては見栄えが悪い。
