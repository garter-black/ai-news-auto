# SNS 動画 v3「画面で見せる型」（試作・未投稿）2026-11-02

v2 へのオーナーの評価:「全体的に質が低い。時間もかかりすぎる」（無関係な写真・文字が多すぎ・題が出っぱなし・変な書体・線や帯だらけ＝AI動画っぽい）。
v3 は製品デモ動画（Apple / Notion / Linear / Screen Studio）・30秒の解説動画・テレビの数字グラフィックを手本に、
**公式ページの本物の画面にズームして証拠を見せ、文字はキーワードだけ**にした。**投稿処理には組み込んでいない。スケジュールも無い。**

## ファイル

| 場所 | 役割 |
|---|---|
| `scripts/shorts_v3.py` | 撮影 → 台本 → 声 → 音 → 絵の計画 → 描画 → ゲート → 見比べ画像。各段階の秒数を report の `timings` に残す |
| `scripts/video_gate.py` | v2 の検査に `check_v3()`（report の `version` が v3 のとき）と `number_context_problems()`・`lint_renderer()` を追加 |
| `scripts/sns_video.py` | `design="v3"` で v3 を作る。速報の「後追い」の約束（6）を追加 |
| `tests/test_shorts_v3.py` | lint・ゲートの単体テストと、合成した料金ページで 270x480/10fps に書き出すゴールデンテスト（ネット・LLM 不要） |
| `.github/workflows/shorts_v3.yml` | 手動実行だけ。VOICEVOX（docker）で本番の声にして Artifacts に MP4・見比べ画像・report を置く |

```
python3 scripts/shorts_v3.py <slug>                  # 本番の声（VOICEVOX）
python3 scripts/shorts_v3.py <slug> --reuse-script   # 台本を使い回す（LLM を呼ばない）
gh workflow run shorts_v3.yml -f slugs="<slug>"      # CI で書き出す（投稿はしない）
```

## 1本の流れ（20〜30秒）

| 時刻 | 画面 | 声 |
|---|---|---|
| 0秒 | 公式ページの本物の画面＋大きな問いかけ1行（例「Claudeの最上位、月200ドルの価値ある？」）。数字が本文の小さな字なら最初はページの大きな見出し | つかみ |
| 0.2〜1秒 | 仮想カメラが数字（例 $200）へズーム。カーソルが動いてクリック、周りを少し暗くする | |
| 1.7秒〜 | 題が消え、答えの数字のキーワード（例 月200ドル）だけ | |
| 3〜24秒 | 4つの場面（順番固定）: ①何が変わった ②得する人（誰の仕事・お金に、なぜ効くか）③向かない人・注意（記事にある条件）④今すること（具体的な次の一歩。証拠はヘルプの Q&A の答えや料金ページの該当プラン）。各場面で「行へ移動 → 数字へズーム（またはページの切り替え・比較グラフ）」の2回、何かが変わる | 1場面1〜2文 |
| 締め | 最初の画面へ引いて戻り、最初の数字へもう一度寄る（最初と最後がつながる）＋答えの1行。**締めのカードは無い**（オーナー指示） | 結論 |
| 最後1.4秒 | 出典の位置に小さく1行「音声 VOICEVOX:冥鳴ひまり　画面 ◯◯（公式）」 | |

- クレジット: VOICEVOX は「VOICEVOX を利用したことがわかるクレジット表記が必要」、冥鳴ひまりの規約は「利用の際はクレジット表記をしてください」で、
  **場所の指定は無い**（2026-11-02 に voicevox.hiroshiba.jp/term と meimeihimari.com/terms-of-use で確認）。説明文（投稿の本文）に必ず入れ、
  転載で説明文が消えても分かるよう、最後の場面に小さな1行も出す。サイトの URL は説明文に入れる（ゲートは v3 では説明文を見る）。
- 撮るページ: 記事の出典が公式（v2 と同じ判定）なら出典ページと、主役の製品の公式料金ページ（`PRODUCT_PAGES`: Claude / ChatGPT・Codex / Gemini）。最大3つ。
  ボット確認の画面・HTTP エラー・ほぼ単色は使わない（ボット対策は回避しない）。ニュースサイトが出典の記事は v3 の対象外（動画なし）。
- 台本（LLM）は記事の事実だけで書き、証拠の場所は「画面の文字」一覧から一文字も変えずに抜き出す。見つからない・キーワードの数字がその行に無いときは書き直させる。
- 画面: 540px 幅・4倍の解像度で撮り（1画面ずつ撮ってつなぐ。Chrome は 16384px を超える1枚を正しく撮れないため）、文字1つずつの位置も測る。
  カメラは ease-in-out、移動中だけモーションブラー。比較グラフ（例 Pro と Ultra、10倍）は記事に倍率があるときだけ。
- 文字: キーワードだけ・題は2秒以内に消す・書体は Noto Sans JP（Black/Bold）だけ・強調色は1色（#FF5C4A）・飾りの線/帯/枠は描かない。
  **数字は記事の表記どおりだけを描く。カウントアップ（途中の数字）は描かない**（止めた画面に記事に無い数字が出るため）。
- 音: VOICEVOX（冥鳴ひまり・行ごとに並列で合成・速さ1.22）。BGM と効果音は**コードで合成した自作**（`synth_bgm`・`sfx_whoosh/pop/click`。外部音源なし＝権利の心配なし）。
  BGM は声が出ている間は声より 15dB 下、行の間は 6dB 上げる。-14 LUFS・ピーク -1.5dBTP。

## 品質ゲート（v3 で追加。どれか外れたら動画は付けない）

| 項目 | 基準 |
|---|---|
| 長さ | 20〜32秒 |
| 画面の変化 | 10回以上・1場面の平均 1.5〜3.0秒・3.6秒を超えて何も変わらない区間なし |
| 動き | 区間ごとのフレーム差（108x192 白黒・10fps）が 0.6 以上。変化と記録した所の直後に本当に絵が変わっている（1.2 以上） |
| 声と BGM の差 | 12〜18dB |
| 題 | つかみの文字は 2秒までに消える |
| 文字の面積 | 1フレームで 18% 以下 |
| 注目の場所 | キーワードが注目の文字にかぶらない |
| 書体 | 2つまで |
| 飾り | 描画のソースに線・帯・枠の呼び出しが無い（マスク・グラフの棒・カーソルだけ許可） |
| 数字 | 描いた文字の数字がすべて記事にある。グラフの倍率は台本どおりで読み上げにもある。数字が記事の中で同じ話題の文に出てくる（別ページの数字の混入を防ぐ） |
| v2 から | 形式・-14 LUFS・無音・字幕とナレーション・安全領域・豆腐・コントラスト・事実・題・クレジット・本番は VOICEVOX |

## 速さ（目標: 記事の公開から動画まで 10 分以内）

各段階の秒数は CI のログと report の `timings`（capture / script / tts / plan_audio / render / gate / sheet）に出る。
手元（M 系 Mac・10コア）: 撮影 5〜12秒・台本 10〜20秒（LLM）・声 5〜6秒・音 1秒・描画 6〜11秒・ゲート 1秒 → 合計 30〜40秒。
CI の実測は下の「CI の結果」。

### 速報の流れ（約束。投稿にはまだつないでいない）

1. 記事が公開されたら、文面の投稿は今までどおりすぐ出す（動画を待たない）。
2. 同時に動画のジョブを起動する（`shorts_v3.yml` と同じ手順。VOICEVOX はジョブの最初に裏で起動）。
3. ゲートに合格した動画だけを公開 URL（R2）に置き、記事の公開から **10 分以内**なら、Threads / Bluesky は同じ投稿への返信、
   X / Facebook は別の投稿として出す。10 分を過ぎたら出さない。
4. 失敗・不合格・時間切れはすべて「動画なし」（文面の投稿はもう出ているので何もしない）。受理不明は再送しない（`sns_video.py` の約束4）。
